# 여행 앱 - 구현 설계

전제 문서: `2026-08-02-travel-app-personas-and-stories.md` (페르소나/요구사항/스토리), `docs/design/design-system.md` (색상/컴포넌트)

## 전체 구조

- **완전 클라이언트형 SPA** — 별도 백엔드 서버 없음. 브라우저에서 구글 로그인 → 브라우저에서 직접 구글시트 API 호출.
- 이유: 여행 날짜/장소는 "언제 어디 있는지"를 드러내는 민감 정보라, 진짜 구글 로그인으로만 접근 가능하게 함 (공개 링크/토큰 방식 배제).
- 구글시트는 화면에 노출되지 않는 **데이터 저장소**. 사람이 보는 화면은 전부 앱이 직접 그림.

## 인증

- Google Identity Services(GIS) OAuth2 토큰 클라이언트를 브라우저에서 사용.
- 스코프: `https://www.googleapis.com/auth/spreadsheets` (읽기+쓰기 — 체크리스트 체크 상태, 입력 폼 저장에 필요).
- 접근 제어는 코드가 아니라 **구글시트 공유 설정**으로 함 — 시트를 혜민/민재 개인 구글 계정에만 "편집자"로 공유. 다른 계정으로 로그인하면 시트 읽기/쓰기가 실패함.
- 토큰은 약 1시간 후 만료 → 만료되면 재로그인 프롬프트 (보통 조용히 자동 처리됨). 캐시된 일정 데이터는 계속 보이므로 데이터 손실/앱 중단 없음.

## 데이터 저장 (Google Sheets, 4개 탭)

| 탭 | 주요 필드 | 비고 |
|---|---|---|
| 여행 (Trips) | 여행ID, 이름, 시작일, 종료일 | 상태(진행중/예정/완료)는 저장 안 하고 오늘 날짜 vs 시작일/종료일로 클라이언트에서 계산 |
| 구간 (Segments) | 구간ID, 여행ID, 도시/숙소명, 구간순서, 시작일, 종료일 | 구간순서는 정렬용 정수(A→B→C 색상 순환용). 시작일/종료일은 개요 카드에 날짜 표시 + "오늘 일정"에서 오늘 날짜가 속한 구간을 찾는 데 사용 (계획 작성 중 발견 — 초안에 빠져 있었음) |
| 일정 (Itinerary items) | 항목ID, 구간ID, 장소명, 주소, 이동수단, 메모, 예약번호, 카테고리, 항목순서 | 시각(HH:MM) 필드 없음 — 항목순서로만 순서 표현. 카테고리="주차"면 항상 골드 강조 |
| 체크리스트 (Checklist) | 체크ID, 여행ID, 항목명, 완료여부 | 여행ID로 여행별 스코프 |

- 외래키: `여행ID`, `구간ID`로 탭 간 연결.
- 이 스키마는 `screen-overview-mockup.html` / `design-system.md`의 화면·컴포넌트 요구사항(구간 커버 카드, 타임라인, 주차 강조)과 1:1로 매핑됨.

## 데이터 입력 (신규 결정)

- 여행/구간/일정/체크리스트 추가·수정은 **앱 안에 직접 만든 입력 폼**으로 함 (구글시트를 직접 열어서 셀 편집하는 방식 아님).
- 이유: SharePoint 리스트 폼 수준의 "보기 좋은" 입력 경험을 원함 — 구글 폼은 관계형(여행ID 등 FK) 구조를 다루기 어렵고 앱 디자인 시스템과도 안 맞음.
- 폼 UI는 `design-system.md`의 색상/타이포/카드 스타일을 그대로 사용.
- 저장 시 Sheets API로 해당 탭에 행 추가/수정 (append/update).

## 오프라인 지원

- **앱 셸(코드/이미지/CSS)**: 서비스워커로 프리캐시 (Vite PWA 플러그인/Workbox 계열) — 오프라인에서도 앱이 열림.
- **일정 데이터**: 마지막으로 불러온 일정 JSON을 로컬(localStorage/IndexedDB)에 캐싱 → 오프라인에서도 조회 가능.
- **체크리스트는 오프라인일 때 조회만 가능** — 체크 탭은 비활성화 + 회색 처리 + "오프라인입니다 · 체크 변경은 온라인에서" 안내. 오프라인 변경을 나중에 동기화하는 기능은 없음 (충돌 처리 복잡도 회피, 의도적 단순화).
- 오프라인 상태는 화면에 명시적으로 표시 (US11).

## 화면 (4개)

| 화면 | 상태 |
|---|---|
| 여행 목록 | 구조 확정 (와이어프레임) |
| 전체 여정 개요 (메인) | 비주얼 확정 |
| 오늘 일정 | 구조 확정 (와이어프레임) |
| 준비물 체크리스트 | 구조 확정 (와이어프레임) |

+ 위 4화면과 별도로, 데이터 입력용 폼 화면들(여행 추가, 구간 추가, 일정 항목 추가, 체크리스트 항목 추가) 신규 필요 — 디자인은 기존 컴포넌트 스타일 재사용, 화면 구조는 구현 단계에서 잡음.

## 기술 스택

- Vite + React + TypeScript
- Google Sheets API v4 (fetch 기반 호출) + Google Identity Services (로그인)
- 서비스워커 기반 PWA (앱 셸 프리캐시)
- 배포: Vercel (기존 예나콩 가족앱과 동일 플랫폼)

## 구글시트 생성 방법

- **방법 B로 진행**: Claude가 구글 드라이브 접근 권한을 받아 4개 탭 구조로 시트를 직접 생성 시도.
- **방법 A (대안)**: 방법 B가 잘 안 되면, Claude가 각 탭의 헤더/샘플 행을 텍스트로 준비하고 혜민이 수동으로 복사해서 시트를 만듦.

## 스코프 밖 (하지 않는 것)

- 오프라인에서 체크리스트/일정 수정 후 온라인 복귀 시 자동 동기화
- 코드 레벨 사용자 허용목록(화이트리스트) — 접근 제어는 시트 공유 설정으로만
- 알림/텔레그램 연동
- 여행 외 다른 데이터(가계부 등) — 기존 예나콩 앱과 완전히 분리된 별개 프로젝트
